# בדיקות — Testing

## הרצה

```bash
npm run typecheck          # TypeScript strict
npm run lint               # ESLint
npm test                   # Vitest — בדיקות יחידה
npx playwright test        # Playwright — דסקטופ + מובייל
npm run build              # בניית ייצור
```

הבדיקות דורשות בסיס נתונים פעיל: `npm run db:server` ואז `npm run db:seed`.

## מה מכוסה כרגע

### בדיקות יחידה — 42 בדיקות, `tests/unit/`

**`pricing.test.ts` (31)** — מנוע התמחור:
- המרת שקלים לאגורות ללא סטיית נקודה צפה (`0.1 + 0.2`)
- דחיית ערכים לא-שלמים במקום עיגול שקט
- עיגול אחוזים לאגורה שלמה
- קופונים: אחוז, סכום קבוע, משלוח חינם, תקרת הנחה, חלון תאריכים, מיצוי,
  מגבלה למשתמש, מינימום הזמנה
- הנחה לעולם לא גדולה מסכום ההזמנה
- משלוח: סף למשלוח חינם, איסוף עצמי, משלוח מהיר, קופון משלוח חינם
- חישוב מחדש של המשלוח **לאחר** ההנחה (מקרה גבול אמיתי)
- סה״כ לעולם לא שלילי

**`fragrance-finder.test.ts` (11)** — מנוע התאמת הניחוח:
- דטרמיניזם: אותן תשובות → אותו דירוג, תמיד
- פרופילים מנוגדים מחזירים משפחות שונות
- ערכים לא מוכרים ב-URL מתעלמים במקום לנחש
- שוויון נפתר בצורה יציבה

### בדיקות דפדפן — 24 בדיקות, `tests/e2e/`

רצות פעמיים: **דסקטופ** (Chrome) ו**מובייל** (Pixel 7).

**`purchase.spec.ts`** — מסלול ההכנסה:
- אורח מוסיף מוצר, עובר לתשלום, מקבל מספר הזמנה `MK-YYYY-NNNNNN`
- מצב הפיתוח מוצג במפורש; **אין** שדות כרטיס אשראי בעמוד
- מוצר שאזל אינו ניתן להוספה
- קופון שגוי נדחה עם נימוק בעברית

**`rtl-and-a11y.spec.ts`** — עברית, RTL ונגישות על 10 מסלולים:
- `lang="he"` ו-`dir="rtl"` בכל עמוד
- **אפס גלילה אופקית** בכל עמוד, בשני הרזולוציות
- בדיוק `h1` אחד בכל עמוד + קישור דילוג לתוכן
- קישור הדילוג מקבל פוקוס ראשון במקלדת
- לכל תמונת מוצר יש `alt`
- מחירים לא מאומתים מסומנים כ״מחיר לדוגמה״
- אין ביקורות או סניפים מומצאים
- מצב `prefers-reduced-motion` — כל התוכן עדיין נגיש
- 404 מחזיר סטטוס 404 ועמוד בעברית

## מה **לא** נבדק

רשימה כנה. אלה פערים אמיתיים, לא השמטות:

| נושא | סיבה |
|---|---|
| **iOS Safari** | Playwright WebKit לא הותקן (הורדה נוספת). המובייל נבדק על Chromium (Pixel 7) בלבד. התנהגות `-webkit-fill-available`, גלילת גומי ו-`100svh` ב-Safari דורשות בדיקה ידנית. |
| **התחברות והרשמה מקצה לקצה** | הזרימה מיושמת ונבדקה בטיפוסים ובבנייה, אך אין לה בדיקת Playwright. |
| **מיזוג עגלת אורח לאחר התחברות** | הקוד קיים (`mergeGuestCartIntoUser`) אך אינו מכוסה בבדיקה. |
| **לוח הניהול** | לא מומש. ראו הדוח הסופי. |
| **תשלום כושל** | ספק הפיתוח תמיד מאשר. נתיב הכישלון קיים בקוד אך לא מופעל בבדיקה. |
| **מרוץ מלאי בין שני קונים** | השריון בטרנזקציה, אך אין בדיקת עומס במקביל. |
| **WebGL חסר** | לא קיים כרגע רכיב 3D באתר, ולכן אין מה לבדוק. |
| **קורא מסך אמיתי** | נבדקו סמנטיקה ופוקוס. לא בוצעה בדיקה עם NVDA/VoiceOver. |
| **צילומי מסך ויזואליים** | חלונית הדפדפן בסביבת הפיתוח לא יצרה פריימים, ולכן לא צולמו צילומי מסך. |

## הוספת בדיקה

בדיקות יחידה נכתבות מול מודולים טהורים (`money`, `pricing`, `fragrance-finder`).
אם לוגיקה עסקית דורשת בסיס נתונים כדי להיבדק, ככל הנראה כדאי לחלץ אותה
לפונקציה טהורה תחילה — כך נבנה `calculateCartTotals`.
